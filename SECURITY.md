# Security Policy

## Challenge bugs

Labs deliberately contain defective code. A behavior explicitly documented as part of a challenge is not, by itself, a repository security vulnerability.

## Real security vulnerabilities

Report risks affecting contributors or their systems: committed secrets, possible container escape, unsafe Docker configuration affecting the host, dependencies that endanger users, unintended remote exposure, or malicious contributed code.

Use GitHub private vulnerability reporting when available. Otherwise contact the maintainer privately through their [GitHub profile](https://github.com/eChrls). Include impact and safe reproduction details. Never post secrets, credentials, personal data, or exploitable proofs in public Issues.
